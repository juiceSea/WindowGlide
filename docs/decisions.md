# 已确认的设计（2026-09-20）

## 工作方式

先评估问题，再获得用户确认后实施；设计答案不代表实施授权。用户已认可移动、缩放、外观与自适应蒙层，要求保持现状，并单独确认了窗口快捷键模块的方案及实施。多屏兼容性与自启动仍是未完成项。

## 功能决策

### 0.4.2 退出快捷键

- 经用户单独确认，将退出键由 Ctrl + Alt + Shift + Q 替换为 Ctrl + Win + Alt + Q；旧组合键不再退出。
- 保留 RegisterHotKey 的占用即拒绝启动规则，同步修改窗口快捷键配置的冲突校验、启动占用检查、实际按键退出测试和部署文档。

### 0.4.1 部署说明与日志保留

- 用户确认提供独立部署说明，以及保留今天及前 6 天、总量约 8 MB 的日志策略；询问性能后明确采用启动一次、运行中每小时一次的休眠等待，不持续监听目录。
- 部署说明面向目标机 Agent，先检查真实 Python/部署路径，验证启动，再创建当前用户 pythonw 快捷方式。开发机不自动设置自启动，另一台机器的真实登录验收留给目标机。
- 日期日志单份约 2 MB；换日、轮转或容量压力时额外清理。普通写入只检查内存大小计数和日期，不扫描目录。大小上限优先于保留完整七天。清理失败重试，无法腾出空间时丢弃新日志。
- 仅管理严格匹配的日期日志；旧版 windowglide.log/.1–.3 按内容时间迁移，保留异常续行。先取得单实例保护再初始化日志，退出前停止维护并关闭文件，再释放单实例，避免重复启动的文件竞争。
- 测试覆盖七天边界、空闲过期清理、换日、总量与单条巨型记录、迁移、多行异常、清理失败重试、正常写入不扫描及线程退出。外观、鼠标和快捷键配置不变。

### 0.4.0 窗口快捷键模块

- 用户提供原脚本 `%USERPROFILE%\Documents\AutoHotkey\TouchpadGestures.ahk`，并自行退出 AutoHotkey。脚本只读核对，未修改。
- 沿用 Ctrl+Win+Alt+J 最小化前台窗口并尝试激活后面的正常窗口、K 恢复最近最小化窗口、M 强制最大化（不是切换）。监听手动最小化，恢复栈去重、容量 100、后进先出、重启清空。
- 用户明确选择恢复最小化前的状态，原最大化窗口恢复后仍最大化。普通窗口保留系统记录的位置和尺寸。手动恢复改变状态后再最小化更新历史状态，不能复用旧的最大化标志。
- 用户要求发生快捷键冲突时本工具优先。已说明 RegisterHotKey 无法任意夺走占用，改用键盘 Hook 可优先拦截，但无法保证超越所有其他 Hook/系统/高权限边界。用户明确确认该限制并授权实现和检查。
- 配置支持 enable_window_shortcuts 及 shortcut_minimize/restore/maximize；精确修饰键匹配，主键按住不重复触发，消费配对主键抬起，真实修饰键始终透传。专门的快捷键匹配接受合成输入以兼容 Windows 触摸板自定义快捷键；自有菜单掩码事件排除，Alt+鼠标的注入过滤保持原样。
- 窗口操作沿用普通权限与系统窗口过滤；按能力跳过不能最小化/最大化的窗口。窗口身份使用 HWND/PID/TID 并监听销毁；正在操作或待激活窗口销毁时取消对应请求。操作异步提交，仅有未完成请求时短时检查状态，结束停止定时器。焦点通过普通 SetForegroundWindow 尝试，不关联其他线程输入队列。
- 测试发现 Windows 最小化后可能自动激活别的窗口，原先过严的“前台不能变化”检查阻止了用户要求的下一正常窗口激活。已允许最小化完成后做一次正常的焦点请求，遵守 Windows 的返回结果；恢复仍避免覆盖已转移到其他窗口的焦点。
- 57 项逻辑测试、10 项快捷键实际桌面场景、10 项移动回归、19 项缩放回归和启动检查通过。真实冲突测试在 WindowGlide 前先注册同组合 M，运行期间竞争注册不收到该键，退出后恢复响应；验证手动/快捷键最小化、最大化恢复、状态更新、逆序、失效记录、连按抑制、拖动清理及菜单/按键释放。空闲两秒抽样 CPU 时间为 0。
- 真实触摸板及常用应用焦点交互仍待用户验收。保留 4 DIP 雾蓝边框、自适应灰白蒙层及精细方向提示。未开启自启动，也未将版本 0.4.0 视为原文档 Phase 4 兼容性完成。

### 鼠标与视觉模块的已确认规则

1. 原生缩放优先；如果 Alt + 右键不能可靠复用原生缩放，允许自定义缩放后备。
2. 最大化窗口左键拖动时还原并保持抓取位置。
3. 最大化窗口右键缩放时，从当前最大化可见尺寸开始，退出最大化，仅调整对应边/角。
4. 松开鼠标、松开 Alt 或按 Esc 均结束操作并保留当前结果，不回滚。
5. 所有可操作窗口默认生效，第一版不提供应用排除名单。
6. 用户在第二阶段验收后调整区域：横纵均为 40% / 20% / 40%；单边缩放限于中间 20% 窄带，四角双边缩放。中央重叠区域 Alt + 右键不缩放且仍拦截菜单，Alt + 左键移动保持不变。从中心按下再拖出中心，本次仍不缩放。此项取代最初的“中心选择最近边”规则。
7. 跳过系统界面和全屏窗口，不绕过权限；固定尺寸窗口不缩放。
8. 蒙层为可配置淡白透明层，不做真正模糊，不替换全系统光标。
9. 基本日志、退出、单实例与异常清理前移至 Phase 1。
10. 开机自启动最后提供脚本，不自动启用。

## 第一阶段移动路线调整：已单独确认并授权

原生原型的自动交互测试发现：

- 低级 Hook 消费左键按下后，测试中目标应用看不到左键按住状态。
- 使用标题栏命中/系统鼠标移动指令未观察到进入移动循环。
- 使用系统键盘移动命令可进入原生模式，但当时的原型没有通过抓取位置、输入状态和结束操作测试。

这仅说明当前原型未通过验证，不证明所有原生实现都不可行。没有把合成输入测试结果冒充真实鼠标手感验证。

向用户说明问题和取舍后，用户明确选择：

> 改用鼠标事件驱动的移动，优先保证拖动和结束行为稳定；暂不承诺原生贴边吸附。

当前版本据此使用合并鼠标事件驱动的异步窗口定位，空闲时不运行位置轮询。第一阶段仅移动，不提前实现缩放、Overlay 或光标样式。

## 人工验收与阶段进度

- 初次人工验收：用户确认 Chrome 普通窗口拖动顺畅，松开鼠标立即停止。随后确认松开 Alt 能停止，但拖动后会触发原应用 Alt 功能。
- 用户已确认并授权菜单屏蔽修复：普通 Alt 和 Alt 快捷键保持原行为，仅对已用于拖动的 Alt 屏蔽额外菜单触发。
- 修复使用整次 Alt 按住期间的拖动标记，不在鼠标松开或 Esc 时提前清除。Alt 释放前发送成对的未分配 `VK_E8`；真实 Alt 释放始终透传。自动测试通过后，用户确认拖动后不再触发 Alt 功能，普通 Alt 和快捷键正常。
- 用户确认 Esc 立即停止且不回滚、不误触菜单；最大化窗口单击不还原、拖动才还原，位置和手感正常。第一阶段本轮验收通过。
- 第二阶段已授权并实现：直接采用事件驱动缩放，遵守应用尺寸约束，不跨过对边翻转，缩放时抑制右键菜单，普通右键保留。自动检查通过，等待真实应用验收。
- 第二阶段首次实测：用户确认右下区域缩放符合预期，另报告“最大化→缩小右边→保持 Alt 再扩大到上限”后左右键均失效。日志与现场状态确认普通带标题栏的窗口被仅按尺寸判断的全屏规则误过滤（窗口可见矩形 0,0,1926,1080，屏幕 0,0,1920,1080）。
- 用户已确认并授权修复全屏识别：有正常标题栏的大窗口继续允许操作，无标题栏且覆盖屏幕的窗口仍跳过。0.2.1 已实现，完整持续 Alt 操作链自动回归通过，等待人工复测。
- 0.2.1 人工复测通过：用户确认扩大到上限后移动和缩放都能继续。
- 用户确认原八方向缩放、对边固定及最小尺寸限制正常，随后提出 20% 窄带和禁用中心右键缩放的变更。经澄清并单独获实施授权，0.2.2 已完成该调整，40 项逻辑测试及 19 项缩放集成检查通过，等待新区域规则的人工复测。
- 更多应用、多屏混合 DPI 和长期稳定性尚未完成实际验收。
- 原生吸附等附带行为不在当前实现保证范围内。

### 0.3.2 雾蓝默认色与 Windows 强调色

- 用户要求默认使用柔和偏蓝的边框，并支持配置是否跟随 Windows 主题色。评估并说明主题色可能鲜艳或与背景对比不足后，用户确认默认 #7C9BC5、use_windows_accent_color=false、读取失败回退配置色，随后追加边框略加粗的要求。
- border_width 默认由 2 改为 3 DIP；用户可自行修改 1–20 DIP，改配置后重启。border_color 默认 #7C9BC5，主题色开启后为后备色。
- 实际实现使用 UISettings.GetColorValue(UIColorType.Accent)，读取用户选择的强调色。前期评估参考了 DwmGetColorizationColor，但它描述的是 DWM 合成颜色；最终采用专门的强调色接口。标准库 ctypes 调用 WinRT，正确配对释放 COM 对象、HSTRING 和线程初始化，无额外依赖、无系统配置写入。
- 每次开始有效操作时查询，只有颜色变化才替换背景画刷并释放旧画刷。未启用或未显示边框时不读主题色，空闲无轮询。失败回退配置色，重复失败不刷日志，可自动恢复。
- 47 项逻辑检查通过，包括开关关闭不查询、下一次读取新颜色、失败回退与恢复。固定雾蓝和真实 Windows 强调色两套完整视觉检查通过，像素与 3 DIP 宽度符合配置。当前机器强调色返回 #394345；不修改用户主题进行测试。固定色首次测试未识别到手势（日志无 armed 和异常），单独重跑通过，不能将该次未进入手势误算成通过。

### 0.3.3 自适应灰/白蒙层

- 用户自行将边框宽度改为 4，已按要求重启验证配置加载；开发后保留该值。
- 用户提出亮窗口使用灰蒙层、暗窗口使用白蒙层。已说明混合内容误判、遮挡和采样不可用、单次手势固定颜色、额外采样耗时等边界；用户明确确认一次采样方案并授权实现、检查和重启。
- adaptive_glass_color 默认开启，关闭回到固定白色；两种色共用 glass_opacity=0.20。亮色用 #40444B，暗色用 #FFFFFF。
- 控制线程在 begin_move/begin_resize 前、反馈隐藏时进行一次客户区内部 80% 区域的 24×24 下采样；平均显示亮度阈值 0.60。采样点检查目标窗口归属；检测到遮挡/离屏、窗口不可用、区域过小、采样失败时用白色。关闭自适应/蒙层及禁用中心缩放均跳过。
- 不调用 PrintWindow，不写截图文件、不上传图像、不记录采样图像；只记选择结果、原因和时间。本机测得采样 19–23ms，不代表所有驱动或 HDR 环境，也不保证无法阻塞；没有逐帧/空闲采样。混合内容、保护内容、小浮层和不参与命中的浮层仍可能误判。
- 52 项逻辑测试、明暗实际像素检查、本次颜色锁定/下一次重新判定、关闭开关、遮挡回退、10 项移动集成与 19 项缩放集成通过，亮/暗截图已检查。遮挡测试最初使用 STATIC 窗口，WindowFromPoint 不将其视为遮挡，改为普通可命中窗口后验证回退；该检测边界已说明，不能声称识别所有遮挡。
- 等待用户在浅色/深色实际应用上验收，以及对起拖手感的反馈。
