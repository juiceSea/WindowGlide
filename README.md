# WindowGlide — 窗口拖动与快捷键工具（0.4.4）

Windows 11 的 **Win / Alt + 左键移动、右键缩放**工具，修饰键由配置选择。仓库附带配置使用 Win。使用普通用户权限，要求 64 位 Python 3.11 或更新版本，当前在 Python 3.14 上验证。无第三方依赖。

移动、缩放、区域划分、自适应蒙层和窗口快捷键已获用户认可。0.4.1 增加七天日志清理与独立的 [部署与自启动说明](部署与自启动说明.md)，保留现有外观和 4 DIP 用户边框配置。多屏混合 DPI 的完整兼容性验收、另一台机器的登录自启动验收仍需完成；版本号不代表原文档的兼容性阶段已完成。

## 启动与退出

双击 `start_windowglide.cmd`。终端出现 `READY` 后即可使用，测试阶段保留这个终端方便观察日志。

也可以在项目目录运行：

```powershell
python main.py
```

- 按住 **Win + 左键**，从窗口客户区拖动。
- 按住 **Win + 右键**，从窗口内部调整所在区域对应的边或角，无需贴着真实边框。
- 松开操作鼠标键、松开所选修饰键或按 Esc：结束移动/缩放，保留当前结果，不回滚。
- **Ctrl + Win + Alt + Q**：退出 WindowGlide。
- 备用退出：双击 `stop_windowglide.cmd`，或者运行 `python main.py --stop`。
- 重复启动不会安装第二组 Hook。
- 退出快捷键已被占用时，启动失败并记录原因，不会留下没有退出方式的后台实例。

需要隐藏终端时可自行运行 `pythonw main.py`，退出方式相同。当前不会自动设置开机启动。

## 选择拖动修饰键

在 `config.json` 中设置 `"drag_modifier": "Win"` 或 `"drag_modifier": "Alt"`，退出并重新启动程序后生效。二者择一，左右两侧的同名修饰键均支持；额外按住 Ctrl、Shift 或另一种修饰键时不开始鼠标操作。旧配置缺少此项时继续使用 Alt，非法值拒绝启动。

两种模式共用移动、缩放、八方向区域、最大化还原、视觉反馈及结束逻辑。Win 模式下，被程序接管的左/右键操作即使没有移动，松开 Win 后也会屏蔽开始菜单；先松鼠标、先松 Win、按 Esc 结束同样处理。单独按 Win、普通 Win 系统快捷键保持原有行为。Alt 模式保留原有菜单行为：拖动和被接管的右键操作屏蔽 Alt 菜单，左键未拖动则不额外屏蔽。

屏蔽使用带标记的中性按键对，真实修饰键松开事件仍传递给系统；发送失败会记录日志。更高权限应用、其他键盘鼠标 Hook 或相同快捷键的软件可能限制效果。使用 Win 模式前，应关闭截图等工具中的 Win＋鼠标同键位绑定，避免争用。

修改 `drag_modifier` 不改变下面的 J/K/M 及退出快捷键。后文早期验收记录保留 Alt 用语；使用 Win 模式复验时，将鼠标手势中的 Alt 换成 Win，并检查拖动后不弹开始菜单、下一次单独按 Win 仍正常打开开始菜单。

## 窗口快捷键与触摸板

| 默认快捷键 | 动作 |
|---|---|
| Ctrl + Win + Alt + J | 最小化当前前台窗口，再尝试激活 Z 序中的下一个正常窗口 |
| Ctrl + Win + Alt + K | 恢复最近最小化的窗口并尝试激活；连续按，按逆序逐个恢复 |
| Ctrl + Win + Alt + M | 强制最大化当前前台窗口，重复按不切换为普通窗口 |

按住主键只触发一次，松开后再按可以再次触发。目标是前台窗口，不是鼠标下窗口。触摸板继续通过 Windows 的自定义快捷键发送上述组合；WindowGlide 接收对应的合成键盘输入，不自行识别触摸板手势，也不修改 Windows 手势设置。原 AutoHotkey 脚本保留未修改，试用时保持它退出，避免双重响应。

实体键盘快捷键在主键按下时立即响应；触摸板等合成快捷键会记住触发时的窗口，等主键和整组修饰键全部释放后，再等待约 50 毫秒调度执行，避免合成输入尚未结束就最小化并切换前台。等待期间如有新的按键、前台或目标进程改变，或 1.5 秒内未收齐松键，则取消该次动作；执行前再次校验目标，上一窗口动作尚未结束时不积压合成操作。无需修改触摸板绑定，不强制清除应用的新消息闪烁提醒。

手动点最小化也会进入恢复栈。同一窗口去重，最多 100 条，重启清空，不补录程序启动前已经最小化的窗口。恢复时跳过已关闭、已恢复或权限不可操作的记录，并校验窗口所属进程/线程。原来最大化的恢复后仍最大化，普通窗口沿用原来的位置和大小；手动恢复、改变状态后再次最小化会更新记录。

J/K/M 使用键盘 Hook 优先拦截，已验证可压过另一个测试程序预先注册的同组合快捷键，程序退出后其他程序可重新收到它。无法保证压过所有其他 Hook、系统保留组合或高权限环境。只拦截精确匹配的组合，额外按 Shift 不匹配默认键位；普通按键透传。退出键 Ctrl+Win+Alt+Q 仍使用原注册方式，占用时依旧拒绝启动。

桌面、任务栏、工具浮窗、无标题后台窗口、全屏、不可用及更高权限窗口会跳过；不绕过 UIPI。窗口操作异步发出，短时定时检查完成后尝试激活，Windows 拒绝焦点请求时只记录日志，不强制关联输入线程。快捷键操作先结束当前鼠标拖动并清理反馈，再执行动作。

在 `config.json` 中修改，重启生效：

```json
"enable_window_shortcuts": true,
"shortcut_minimize": "Ctrl+Win+Alt+J",
"shortcut_restore": "Ctrl+Win+Alt+K",
"shortcut_maximize": "Ctrl+Win+Alt+M"
```

关闭 `enable_window_shortcuts` 会同时关闭这三个按键及最小化事件记录，鼠标拖动继续生效。键位支持 Ctrl、Alt、Shift、Win 加 A–Z、0–9 或 F1–F24，至少包含 Ctrl/Alt/Win 之一；三项不能重复，也不能与退出键相同。配置错误拒绝启动，不猜测错误键位。

人工验收：先在 Chrome 用 M 最大化、J 最小化、K 恢复，应仍然最大化；再手动最小化两个普通窗口，用 K 连续恢复，检查逆序及焦点。最后用原触摸板手势重复，并留意额外菜单、开始菜单、卡键和重复触发。真实触摸板不能由合成输入自动测试替代。

## 第一轮人工验收

本轮移动验收已完成：用户确认普通移动顺畅、松开左键/Alt 停止、Esc 不回滚、最大化还原自然。首次验收发现拖动后误触 Alt 菜单，修复后用户确认拖动后不再误触，普通 Alt 与快捷键仍正常。下面保留可复用的移动验收步骤。

现在请先测试 **Alt + 左键拖动 Chrome 的非最大化窗口**：在网页空白处按住，慢慢拖动，然后快速拖动，最后松开左键。

接着测试：

1. 在内容区按住 Alt + 左键，拖动时先松开 Alt，再松开鼠标。窗口应立即停止；鼠标随后移动不能继续带动窗口。
2. 拖动时按 Esc。窗口应留在当前位置，不能回到起点。
3. 最大化 Chrome 后拖动。窗口应还原，抓取点按窗口内的相对位置计算；仅 Alt + 单击不应还原。
4. 留意松开 Alt 后是否激活 Chrome 菜单、系统菜单或留下异常键盘状态。
5. 用资源管理器、Windows 记事本、一个常用 Electron 应用重复前面的基本拖动测试。
6. 如果有多屏，测试跨屏和不同缩放比例。自动测试没有替代这些真实环境验证。
7. 按退出快捷键，再尝试 Alt + 拖动。WindowGlide 应不再生效。

请反馈具体应用、是否最大化、缩放比例，以及跳动、卡顿、菜单弹出或停止不及时等现象。可提供 `logs/windowglide.YYYY-MM-DD.NNNNNN.log` 的对应时间段；日志包含被操作窗口的标题，分享前请检查是否有私人内容。

## 第二阶段缩放验收

首先在 Chrome 非最大化窗口的**右下区域**按住 Alt + 右键，拖动并松开；右边和下边应随鼠标变化，左边与上边保持原位。再验证：

1. 四角以及四条边对应的区域，确认共八个方向自然。横向和纵向都按 40% / 20% / 40% 划分：只有中间 20% 的窄带使用单边缩放，其余四角使用双边缩放。
2. 缩小时到达应用最小尺寸后停止，不翻转；松开右键、松开 Alt、按 Esc 都停止且保留尺寸。
3. 缩放结束不弹出右键菜单/Alt 菜单；普通右键菜单、普通 Alt 快捷键仍正常。
4. 最大化后在左右侧中间区域拖动：从当前可见尺寸开始，退出最大化，只调整所选边；不先跳回以前的小窗口。Alt + 右键单击但不拖动不应还原。
5. 重复一次 Alt + 左键移动，确认没有影响第一阶段功能。
6. 在中央 20% × 20% 重叠区域 Alt + 右键单击或拖动：窗口不移动、不缩放、不从最大化还原，并拦截右键菜单及随后额外的 Alt 菜单。从中心按下后拖出中心也不开始缩放；中心 Alt + 左键仍可移动。

| | 左侧 40% | 中间 20% | 右侧 40% |
|---|---|---|---|
| 上部 40% | 左上角 | 上边 | 右上角 |
| 中间 20% | 左边 | 不缩放，拦截菜单 | 右边 |
| 下部 40% | 左下角 | 下边 | 右下角 |

## 第三阶段视觉反馈与配置

实际开始移动或缩放后显示雾蓝边框（或所选颜色）、自适应灰/白蒙层，以及鼠标旁的方向图标。松开操作鼠标键、松开 Alt、按 Esc、切换前台或关闭目标窗口时清理。只按下而未拖动、中心禁用区域的 Alt + 右键都不显示操作反馈。

原生光标切换没有通过跨应用测试；经用户确认，改为**保留原鼠标，在旁边显示方向提示**。不修改系统光标，不关联外部应用输入线程。方向提示为 32 DIP 石墨灰圆角底板、轻描边和柔白线条箭头，通常位于鼠标右下方，接近屏幕边缘时移到另一侧。图案抗锯齿绘制并按方向、像素尺寸缓存，仅图案改变时上传；移动时只更新位置。真实跟随手感仍需人工验收。

编辑根目录 `config.json` 后重启生效。支持部分配置，缺少字段沿用默认值；格式或字段错误会拒绝启动并记录日志，不静默忽略。

| 配置 | 默认值 | 说明 |
|---|---|---|
| `drag_modifier` | `"Alt"` | `"Alt"` 或 `"Win"`；缺省兼容旧配置，仓库附带配置为 Win，重启生效 |
| `border_width` | `3` | 边框宽度，1–20 DIP；可以改为 4 等值进一步加粗 |
| `border_color` | `"#7C9BC5"` | 雾蓝，六位 RGB 颜色；主题色读取失败时也使用此色 |
| `use_windows_accent_color` | `false` | 改为 true 后跟随 Windows 强调色，优先于 border_color |
| `glass_opacity` | `0.20` | 灰/白蒙层共用的不透明度，0–1；不是背景模糊 |
| `adaptive_glass_color` | `true` | 按操作开始时的内容亮度选择灰/白；false 恢复固定白色 |
| `corner_radius` | `8` | 圆角，0–32 DIP；最大化或明确禁用圆角的窗口使用直角 |
| `enable_border` | `true` | 显示边框 |
| `enable_glass` | `true` | 显示蒙层 |
| `enable_cursor_change` | `true` | 保留原配置名称，现控制鼠标旁方向提示，不更换鼠标 |

可使用 `python main.py --config 路径` 指定其他配置。关闭所有视觉效果仍可移动和缩放。

主题色开关使用 JSON 布尔值 `true` / `false`，不要加引号。编辑配置后先运行 `stop_windowglide.cmd`，再运行 `start_windowglide.cmd`。启用跟随后，每次实际开始移动或缩放时通过 Windows `UISettings.GetColorValue(Accent)` 读取当前强调色，系统换色会在下一次操作生效；空闲时不轮询。读取失败回退到 `border_color`，仅首次失败记警告，恢复后可继续跟随。不会修改 Windows 配色或注册表。强调色保持系统原色，可能偏亮、偏暗或高饱和，未做自动调色。

自适应蒙层只在每次手势跨过拖动阈值时、窗口移动/还原及蒙层显示前采样一次。取客户区内部 80% 区域，缩小为 24×24 像素，按平均显示亮度判断：达到 60% 用 `#40444B` 灰色，否则用白色；本次手势中保持不变。采样不在 Hook 内运行，不使用 PrintWindow，不保存或上传图像；日志仅记录选择、原因和耗时。关闭自适应或蒙层、中心禁用缩放区域均不采样。

本机测试的单次采样约 19–23ms，发生在开始操作时，仍需人工评估起拖手感；空闲及持续拖动无亮度轮询。采样位置检测到遮挡/离屏、内容太小或读取报错时回退白色。混合明暗内容、视频、受保护内容、HDR，以及采样点之间或不参与鼠标命中的浮层可能导致误判；这是内容亮度近似判断，不是应用主题识别。跨显示器与不同图形驱动仍需后续兼容性验收。

人工试用：在 Chrome 非最大化窗口上分别 Alt + 左键移动、Alt + 右键缩放，检查边框贴合、蒙层亮度、方向提示和拖动流畅度；分别松开鼠标、松开 Alt、按 Esc，确认没有残留。再测试最大化窗口和中心禁用区域。不同 DPI、多显示器及长时间运行留待后续兼容性验收。

## 实现与已知边界

- 经用户确认，原生拖动原型验证失败后，改用鼠标事件驱动的 `SetWindowPos` 移动。密集事件合并为约 16ms 一次的位置提交，闲置时没有轮询定时器。
- 第二阶段经单独确认直接沿用事件驱动缩放。按下区域决定本次方向，拖动过程中不切换方向；保持对边位置，并按应用通过 `WM_GETMINMAXINFO` 返回的跟踪尺寸限制缩放。查询超时为 150ms，失败则跳过本次缩放，不在 Hook 内等待。
- 最大化缩放按 DWM 可见区域和 Windows 11 普通边框尺寸还原，避免先恢复到旧的小尺寸；自绘边框和混合 DPI 的真实应用兼容性仍需验收。尺寸限制在每次操作开始时读取，拖动中跨 DPI 的限制刷新留待兼容性阶段验证。
- 控制线程执行窗口操作，独立 Hook 线程只识别手势、做少量窗口筛选并转交事件。定位请求使用异步标志，避免等待目标应用的 UI 线程。
- 第一版**不承诺 Windows 原生贴边吸附、Aero Shake 等原生拖动附带行为**。
- 普通窗口保持鼠标与窗口的固定偏移。最大化窗口恢复为原来的普通尺寸，保持相对抓取位置，并尽量让标题栏留在屏幕内；到达屏幕边界时可能调整位置。
- **操作后的 Alt 菜单抑制**：左键实际拖动或本工具接管的 Alt + 右键操作，都会在 Alt 松开前发送成对的未分配键 `VK_E8`，屏蔽额外菜单激活。中心右键无缩放操作也会抑制菜单。普通 Alt、Alt + 字母快捷键不做此处理；真实 Alt 释放始终透传，不吞掉、不重放。辅助事件有独立标记，不参与本工具的手势识别。权限导致发送失败时记录日志并保留真实按键释放。
- 普通运行的 Alt+鼠标手势忽略合成输入；窗口快捷键则接受匹配的合成键盘组合，以支持触摸板。真实鼠标和触摸板仍需人工验收。
- 为避免 AltGr 及组合快捷键冲突，开始手势时只接受 Alt，不同时接受 Ctrl、Shift、Win。拖动中仍可使用退出快捷键。
- 默认覆盖所有可操作窗口，第一版没有应用排除名单。会接管这些窗口的 Alt + 左/右键点击；Alt + 单击但不拖动也不会透传为普通点击。固定尺寸窗口不拦截 Alt + 右键，以保留其原操作。
- 跳过桌面、任务栏、常见系统界面、全屏、隐藏或不可用窗口。特殊无边框应用可能被跳过，需按实际反馈调整。
- 全屏判断同时考虑标题栏样式：有正常标题栏的窗口即使铺满或超过屏幕仍可操作；无标题栏且覆盖屏幕的窗口按全屏跳过。已修复最大化缩小后重新扩大到上限导致普通窗口被误判全屏的问题，并加入持续按住 Alt 的完整操作链测试。
- 权限检查失败或遇到更高完整性级别的窗口时跳过并记录日志，不提权、不绕过 UIPI。此类被后续检查拒绝的 Alt 点击可能被消费，但不会重放到应用，以免产生意外操作。
- Windows 拒绝前台激活时不强制抢焦点；允许移动符合条件的后台窗口。拖动期间前台切换、窗口关闭/最小化、目标无响应时会清理手势。
- 尚未验证长时间运行、管理员应用、游戏/独占全屏、混合 DPI 和全部 Chromium/Electron 版本的真实交互。

视觉检查验证实际窗口位置、层级、焦点、鼠标穿透、截图颜色、方向提示及退出清理。报告和测试窗口截图位于 `test-results/`；自动测试不能代替 Chrome 的真实操作手感验收。

日志写入 `logs/windowglide.YYYY-MM-DD.NNNNNN.log`，按本机日期保留今天及前 6 天；单份约 2 MB，总量上限约 8 MB，超过上限优先删除最旧文件，因此可能不足七天。不逐帧记录鼠标移动。

启动时清理，后台休眠线程每小时唤醒清理一次；换日、文件轮转或容量达到上限时也检查。普通日志写入只检查日期和内存中的大小计数，不逐条遍历目录；没有目录监听或逐秒轮询。关闭期间不运行，下次启动补清理。只处理严格匹配本程序命名的日志，失败后重试；无法腾出容量时丢弃新记录，避免持续增长。旧版 windowglide.log 和 .1–.3 首次启动时按记录日期迁移，过期记录清除，多行异常沿用前一条记录日期；无法识别日期的开头沿用源文件修改日期。清理范围不包括 test-results 或其他应用日志。
